# Architecture

[Deutsche Version](../de/architektur.md) · [Overview](README.md)

## Modules

| File | Purpose | DOM |
|---|---|---|
| `js/cards.js` | cards as numbers 0 to 51, seeded randomness, shuffle, deal | no |
| `js/game.js` | game logic: moves, rules, scoring, undo, saving, detecting a dead end | no |
| `js/solver.js` | depth-first solver, hint for a position | no |
| `js/solver-worker.js` | solver in the background | worker |
| `js/levels.js` | levels, next deal number, daily deal | no |
| `js/deals.js` | sorted deal numbers, generated by `tools/deals.mjs` | no |
| `js/faces.js` | the deck as SVG symbols | no |
| `js/view.js` | mat, layout, tap and drag, animation | yes |
| `js/celebrate.js` | win celebration on a canvas | yes |
| `js/sound.js` | sounds, a subclass of the shell's sound engine | Web Audio |
| `js/main.js` | connects everything to the shell: levels, rules, statistics, time | yes |

## Data model

```
card        number 0 to 51. suit = card / 13 (spades, hearts, clubs, diamonds), rank = card % 13 + 1
tableau     7 × { down: [face down], up: [face up] }, last card on top
foundations [4] highest rank per suit
stock       the next card to draw comes first
waste       the top card comes last
fan         how many cards of the last draw are fanned out
```

Undo stores a snapshot before every move. A game is saved after every move and every 5 seconds and resumed on the next start.

## Solver

The solver knows every card. It treats waste and stock as **one row** with a position: drawing moves the position forward, passing again resets it to zero. Instead of single draw moves it only knows "play the card at position p", which saves a great deal of search.

* **Safe moves first and alone:** a card may go to a foundation safely when every card that could be placed on it is already there.
* **Order:** foundation, revealing (columns with many face-down cards first), cards from the stock, partial runs that free a card for a foundation, emptying columns, back from a foundation.
* **Known positions** are never searched twice. Columns are sorted for this, since their order does not matter.
* **Budget:** a hint examines at most 60,000 positions, which takes well under a second on an iPhone.

## Flow of a move

1. `view.js` recognises a tap or drag and reports `tap(from)` or `move(from, to)`.
2. For a tap, `main.js` picks the best target (`game.bestTarget`) and plays the move.
3. `game.js` checks, moves, reveals, scores and remembers the position for undo.
4. `view.js` computes every card's target position and moves it with `transform`.
5. `main.js` plays the sound, saves and checks: won, automatic finish or stuck.

## Development and tests

```bash
npm start                        # http://localhost:3000/karo/
npm test                         # logic tests, including karo/tests/
npm run e2e                      # browser test of every game
node karo/tools/deals.mjs 200    # re-sort the levels
node karo/tools/icons.mjs        # regenerate the app icons (needs Playwright)
```

| Test | Checks |
|---|---|
| `tests/game.test.js` | dealing, rules, scoring, Vegas, time, undo, saving, game end |
| `tests/solver.test.js` | solutions can be replayed move by move in the real game |
| `tests/levels.test.js` | lists are unique, sample is solvable, order, daily deal |

KARO does not change the shell. New version: `node scripts/release.mjs karo <version>`.
